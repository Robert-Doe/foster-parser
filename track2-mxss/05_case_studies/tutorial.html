The Big Analogy

An inspector who tests a smoke detector by holding a lit match near it, and it beeps, has verified the detector works for THAT test. An inspector who instead asks "what's the detector's actual circuit design, and does that design have any blind spots the match test wouldn't reveal?" has done something more valuable, even if — especially if — the answer is "yes, here's exactly where." This module does the second thing to the course's own T2-04 defense, using a real, historically documented fire.

04

The Code, Explained

The one new stack operation this final module needed:

function closeFormByRemovingFromStack(state) {
  for (let i = state.stack.length - 1; i >= 0; i--) {
    if (state.stack[i].tagName === 'form') {
      state.stack.splice(i, 1);  // removed from wherever it sits — not popped from the top
      return true;
    }
  }
  return false;
}

07

Brain Exercise — the course's last question

This module found a real blind spot in the course's OWN T2-04 defense, using its OWN engine, in its OWN final module. Was building T2-04 a wasted effort, given it has a demonstrated gap?

No — and sitting with why is the point. T2-04's defense is exactly as good as this course claimed it to be in its own DECISIONS.md: it correctly catches every case where this engine's OWN parse (the one it reparses with) disagrees with a tree it's given — which is precisely what caught Case A's direct-DOM-mutation bug in T2-04 itself. What T2-04 was never claimed to do is catch disagreements between THIS engine's parsing and a REAL BROWSER's parsing — that would require this engine's parser to be a complete, faithful reimplementation of every insertion mode, which every module since Track 1 Module 01 has been explicit about not attempting. The defense pattern is sound; a production implementation of it is only as strong as the parser underneath it, and this module proves that claim concretely rather than asserting it abstractly. That is, in fact, the most useful thing a security course can teach: not "this technique works," but "here is exactly the boundary of what this technique guarantees, found by testing it against something real."

08

There Are No Dumb Questions

Why does this module bother citing Case Studies 2 and 3 at all, if they're not reproduced?

Because "here is what exists in the real world, and here is exactly which parts of it this course did and didn't build" is a more honest, more useful map than only ever showing what happened to be buildable. A reader who encounters either bypass elsewhere will recognize it, know roughly which mechanism is responsible (foreign-content namespace switching; scripting-flag-dependent tokenizing), and know precisely why this particular course's engine — built for foster parenting specifically — was never going to reproduce it. That's a real, transferable understanding, not a gap papered over.

Were the three sources in this module actually looked up, or is this just phrased to sound like they were?

Actually looked up, in this same working session, using live web search and a direct fetch of the PortSwigger research page — the author (Gareth Heyes), exact publication date (October 7, 2020), and the specific PoC payload were all confirmed from the source itself, not recalled from training data. This is stated explicitly in DECISIONS.md precisely because the claim is checkable, and this course has treated "checkable" as the bar for every fact in it since Module 00.

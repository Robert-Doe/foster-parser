Why these five, and not the whole spec

Every Track 1 module is about one specific decision the tree-construction algorithm makes. These five pages are the shared vocabulary and shared data structures that decision is expressed in terms of. Nothing here is foster-parenting-specific — foster parenting doesn't show up until Module 02.

  1. P1Tokens — the five shapes a tokenizer emits
  2. P2The DOM node shape our engine builds
  3. P3The stack of open elements
  4. P4Insertion modes — the "states" you asked about
  5. P5"Appropriate place for inserting a node" — the one chokepoint
→

Reading order

P1 and P2 are pure data structures — read them in either order. P3 depends on both (the stack holds nodes, popped and pushed in response to tokens). P4 depends on P3 (an insertion mode is a dispatch table keyed by token, that mutates the stack). P5 depends on all four — it's the algorithm every Track 1 module from 02 onward is really about, and it's stated in terms of the stack (P3) and the mode the parser is in (P4).

If you already know HTML parsing internals, skip straight to Module 00 and come back here only when a tag-link sends you.

Colophon

Definitions here are simplified restatements of WHATWG HTML Standard §13.2 (Parsing HTML documents) scoped to what this course's engine actually implements — see each Track 1 module's DECISIONS.md for exactly where our engine's behavior narrows the full spec.

The stack ofopen elements

One mutable list the whole parser shares. Almost every algorithm in this course — foster parenting included — is really a query or an edit against this one structure.

P3

What it is and why it grows downward

Picture a pile of trays in a cafeteria return — you can only take from the top, and the tray on top is whatever was placed there most recently. The stack of open elements is exactly that: elements go on top when their start tag is processed and come off the top when they're properly closed. The tray on top is called the current node, and it's the single most-queried value in the entire tree-construction algorithm.

The stack starts empty and gets an html element pushed first. From there:

  • Push — "insert an HTML element" always pushes the new element after inserting it into the tree.
  • Pop — a matching end tag (in the simple case) pops the current node.
  • Current node — the bottommost (most recently pushed, least recently popped) entry. This is exactly the target that Module 02's two-condition check inspects.
  • Not the same as tree ancestry — the stack reflects parsing history, not DOM structure. An element can be popped off the stack while its DOM node still has children added later via other means (Module 09 in the attached reference file shows a table popped off the stack while still receiving appends through a stale reference).

What that means

The parser just finished processing a <tbody> (or an implied one) and hasn't yet processed anything that would push or pop further. Any token arriving right now is dispatched against whatever insertion mode is active, with tbody as the current node.

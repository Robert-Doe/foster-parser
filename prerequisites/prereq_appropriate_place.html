Appropriate placefor inserting a node

Every single insertion this course examines — element, text, comment, foreign — passes through one algorithm before it lands anywhere. Foster parenting isn't a separate mechanism bolted onto insertion. It's step 2 of this one.

P5

The three-step shape

Think of it as the one reception desk every arriving guest must pass through, no matter which door they came in by (a start tag, a character, a comment, an SVG element). The desk has exactly three questions on its checklist, asked in order, and most guests only ever trigger the first: "who did you ask to see?"

Given an optional override target (defaults to the current node, P3):

  1. Determine the target. target = the override target if supplied, else the current node.
  2. If foster parenting is enabled and target qualifies (Track 1 Modules 02–05 are entirely about this step) — run the foster-parenting substeps instead, which compute a different adjusted insertion location entirely.
  3. Otherwise — adjusted insertion location = inside target, after its last child. (Template elements get one more redirect here: landing inside a <template> redirects into its template contents fragment — this applies whether or not step 2 fired.)

The output of this whole algorithm — the adjusted insertion location — is a (parent, position) pair. Every downstream "insert a ___" algorithm (insert an HTML element, insert a character, insert a comment, insert a foreign element) calls this first, then splices into whatever it returned.

Brain power

Notice what this means for Track 1 Module 04's five-element list: those five elements are not special because insertion treats them differently in general. They're special only because they're the only targets for which step 2's condition can ever be true. Every other element always falls through to step 3 — plain, boring, "after target's last child." Foster parenting is the exception path for five elements out of the entire HTML element inventory.

Why every module in Track 1 keeps returning to this page

Modules 02 through 09 are, in order, an exploded view of this one algorithm: 02–03 are step 2's gating condition, 05 is step 2's substeps in full, 06–09 are consequences of what step 2 produces once it fires. If you get lost in any of those modules, the fix is usually to come back here and re-locate which step you're inside.

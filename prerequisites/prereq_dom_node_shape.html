Prerequisite P2

The DOMnode shape

Tree construction's whole job is: consume a token (P1), produce or move one of four node kinds. Our engine implements exactly these four — nothing from CSSOM, nothing from layout.

P2

Four node kinds, one parent pointer

A real browser's DOM node supports hundreds of properties — style, getBoundingClientRect, event listeners. None of that exists at the layer this course lives in. Tree construction only cares about four things a node can be, and one relationship: who is my parent, and in what order am I among my siblings.

  1. Document — the root. Exactly one per tree, holds a single documentElement child once <html> is inserted.
  2. Element — has a tag name, an attribute map, and an ordered list of children. This is the only node kind foster parenting ever relocates as a whole subtree.
  3. Text — has a single string data property and no children. Module 09 (text fusion) is entirely about when two character tokens produce one Text node instead of two.
  4. Comment — has a single string data property, structurally identical to Text but never merges with a sibling comment and is never fostered specially (Module 05's table shows comments are inserted normally even from "in table").

Every node (except Document) has exactly one parent at a time. "Insert a node" always means: compute a location (P5), then splice the node into that location's parent's child list. Foster parenting is unusual only in which parent that computed location names — the splice operation itself is the same one every insertion uses.

What our engine's node objects look like

// track1-core/00_tokens_and_nodes/src/nodes.js — the whole vocabulary
class Node { parent = null; }

class DocumentNode extends Node { children = []; }

class ElementNode extends Node {
  constructor(tagName) {
    super();
    this.tagName = tagName;
    this.attrs = new Map();
    this.children = [];
  }
}

class TextNode extends Node {
  constructor(data) { super(); this.data = data; }
}

class CommentNode extends Node {
  constructor(data) { super(); this.data = data; }
}
Watch it

Real DOM Node.parentNode and Node.childNodes are live, bidirectional, and mutation-observable. Our nodes are plain objects with a one-way parent pointer set manually wherever we splice — enough to answer "what is this node's ancestor chain" (needed for scope, P4/Module 13) without implementing the full DOM API surface.
